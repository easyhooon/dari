The Dari desktop app shows the bridge messages of a connected debug build on your computer: a live list, the request and response side by side, and foldable JSON. It needs `dari` 2.0.0 or later and works with real devices and emulators. It runs on macOS and, in preview, Windows; a Linux build is planned.

## Install

### macOS from Terminal

The quickest way. It picks the build for your Mac's chip, checks it against the release's SHA-256
file, and installs or updates `/Applications/Dari.app`:

```bash
curl -fsSL https://raw.githubusercontent.com/easyhooon/dari/main/scripts/install-desktop.sh | bash
```

The checksum is what catches a bad download, so run the command only from this page or the
repository. To pin a version, put `DARI_VERSION=2.0.0` before `bash`.

### macOS from the DMG

1. Download `Dari-<version>-arm64.dmg` (Apple Silicon) or `Dari-<version>-x64.dmg` (Intel) from the [download page](/download) or the [releases page](https://github.com/easyhooon/dari/releases).
2. Open the image and drag **Dari** into **Applications**.
3. Optionally, compare `shasum -a 256 Dari-<version>-arm64.dmg` with the `.sha256` file from the same release. A match means the download isn't corrupted; it doesn't prove who published it.

Dari is signed with a Developer ID and notarized by Apple, so it opens without a security prompt. Download it only from the repository's releases page.

### Windows (preview)

1. Download `Dari-<version>-x64.msi` from the [releases page](https://github.com/easyhooon/dari/releases) and run it. It installs for the current user only.
2. The installer isn't code-signed, so SmartScreen may warn on first run. Click **More info → Run anyway**.
3. Optionally, compare `certutil -hashfile Dari-<version>-x64.msi SHA256` with the `.sha256` file from the same release.

### Download size

Measured on 2.2.0, the macOS download is about 11 MB larger than the Windows one:

| | Windows (`.msi`) | macOS (`.dmg`, Apple Silicon) |
| --- | --- | --- |
| Unpacked | 119.3 MB | 127.1 MB |
| Compression | `MSZIP` | `UDZO` (zlib level 1) |
| Download | 59.6 MB | 70.7 MB |

Both hold the same app: a Java runtime trimmed by jlink, the app's jars, and Skiko, the native Skia library that Compose draws with. Both also compress with Deflate, the LZ77 + Huffman coding algorithm behind zip and gzip:

- **`MSZIP`**: an MSI keeps its files in a CAB archive, and `MSZIP` compresses them with Deflate in 32 KB blocks. jpackage leaves WiX at this default.
- **`UDZO`**: a DMG is a compressed disk image, and `UDZO` compresses it with zlib, a thin wrapper around Deflate. `hdiutil` uses zlib level 1, the fastest and weakest, unless told otherwise.

So the gap has two causes:

1. **Larger native libraries on macOS.** `libskiko-macos-arm64.dylib` is 20.8 MB and `libjvm.dylib` 15.7 MB; on Windows, no file but the runtime's `lib/modules` exceeds 12.7 MB. Deflated file by file, the macOS app comes to 65.8 MB, against the 58.4 MB Windows cabinet.
2. **zlib level 1.** It adds about 5 MB more.

To measure the macOS side:

```bash
./gradlew :dari-desktop-app:createDistributable
cd dari-desktop-app/build/compose/binaries/main/app
du -sh Dari.app Dari.app/Contents/runtime Dari.app/Contents/app
hdiutil create -srcfolder Dari.app -format UDZO -imagekey zlib-level=9 Dari-level9.dmg
```

```
121M	Dari.app
 66M	Dari.app/Contents/runtime
 54M	Dari.app/Contents/app
```

`du -h` counts in MiB, so 121M is 127 MB. The same `Dari.app` in other DMG formats:

| Format | Algorithm | Opens on | Size |
| --- | --- | --- | --- |
| `UDZO`, level 1 (`hdiutil` default) | zlib (Deflate) | Every macOS | 70.8 MB |
| `UDZO`, level 9 | zlib (Deflate) | Every macOS | 67.3 MB |
| `ULFO` | LZFSE: Apple's LZ77 with finite-state entropy coding, built for fast decompression | macOS 10.11+ | 67.3 MB |
| `ULMO` | LZMA: LZ77 with a large dictionary and range coding, as in 7-Zip and xz | macOS 10.15+ | 59.5 MB |

Releases after 2.2.0 use `UDZO` at level 9, which opens on every macOS that Dari supports (10.13 and later). `ULMO` would match the Windows size but needs macOS 10.15.

### Updates

Dari checks the releases page on launch and every six hours. When a newer version exists, an **Update to &lt;version&gt;** button appears in the title bar, and **Help → Install Dari &lt;version&gt;** does the same.

- **macOS**: Dari downloads the new image, checks its `.sha256`, bundle ID, version and code signature, then quits and relaunches as the new version. If anything fails, the installed version is kept. This works when Dari sits in a folder you can write to, such as **Applications**; otherwise Dari tells you to move it to **Applications** and open it from there.
- **Windows**: the button opens the download page. Run the new `.msi`; it upgrades the installed copy.

## Connect

1. Keep `adb` available. Android Studio in its default location already includes it, and Dari also checks `ANDROID_HOME`. Without Android Studio, install [SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools): `brew install android-platform-tools` on macOS, or on Windows unzip it and add the `platform-tools` folder to `PATH`.
2. Connect a device with USB debugging on, or start an emulator.
3. Run a debuggable build of your app that uses `dari` and bring it to the foreground.

Dari finds the device and the app on its own and connects. With several devices, pick one from the title bar, or start Dari with `ANDROID_SERIAL` set. If the device hides its app list, type the applicationId instead.

While the desktop app is connected, the in-app notification and shake-to-open pause; they come back when it disconnects.

## How it connects

There is nothing to configure: no proxy, certificate, Wi-Fi or port.

1. Your app opens a named socket, `dari_<applicationId>`, that only exists inside the device.
2. The desktop app runs `adb forward tcp:0 localabstract:dari_<applicationId>`. This opens a free port on your computer, chosen by adb, and tunnels it over USB to that socket.
3. The desktop app talks to `127.0.0.1:<port>`, and adb carries the data to your app.

Tunnels are removed when the desktop app disconnects or quits. `adb forward --list` shows any open ones.

## Privacy

- **Debug builds only, unless you opt in.** The socket opens only in debuggable builds, or in a non-debuggable internal build that sets the manifest flag below. Release builds use `dari-noop`, which contains no capture code.
- **adb only.** Only adb (shell) or root can connect, so other apps on the device can't read messages.
- **Masking is opt-in.** By default, the desktop app receives payloads as captured, whatever the in-app setting is. Turn on **Mask sensitive values** in the desktop app's settings, and the device masks values under keys such as `token`, `password`, `secret`, `cookie` or `authorization`, and `Bearer` credentials, before they leave it. This is separate from the in-app setting. Apps on dari older than 2.2.0 always mask. See [Masking](./masking) for the exact rules.
- **Nothing about you leaves your computer.** The desktop app has no analytics or telemetry. Its only network request is the update check: a request to `github.com` on launch and every six hours, which sends nothing but what any browser visit would. `dari.log` stays local and records failures only.

Add your own masking. It runs on every message, after the built-in masking when that is on, and if it throws, the message isn't sent:

```kotlin
Dari.setPayloadRedactor { entry ->
    entry.copy(requestData = entry.requestData?.replace(Regex("\"phone\":\"[^\"]*\""), "\"phone\":\"***\""))
}
```

To keep the socket closed entirely:

```kotlin
Dari.setDesktopInspectorEnabled(false)
```

A non-debuggable internal build, such as staging, can opt in with this entry in its manifest:

```xml
<meta-data
    android:name="com.easyhooon.dari.desktop.ALLOW_NON_DEBUGGABLE"
    android:value="true" />
```

## Desktop only

For builds where only the desktop app should show messages, such as a staging build used for QA, add this entry. Dari then shows no notification, doesn't open on shake, and removes its launcher shortcut. Messages are still captured, and the desktop app shows them as usual.

```xml
<meta-data
    android:name="com.easyhooon.dari.DESKTOP_ONLY"
    android:value="true" />
```

A non-debuggable build needs `ALLOW_NON_DEBUGGABLE` above as well; otherwise nothing can show its messages.

## Troubleshooting

| Status | What to do |
| --- | --- |
| adb not found | Set `ANDROID_HOME`, or add `platform-tools` to `PATH`, then reopen Dari. |
| No device | Check `adb devices`. Accept the USB debugging prompt on the device. |
| App is in the background | Android pauses background apps. Bring the app to the foreground and Dari reconnects. |
| Not running Dari | Check that the app is a debuggable build using `dari` 2.0.0 or later. |

To report a problem, use **Help → Report an Issue…**. It opens the bug form with your Dari version and OS filled in; **Help → Suggest a Feature…** opens the feature request form. **Help → Show Log File** opens the folder with `dari.log` (`~/Library/Logs/Dari` on macOS, `%LOCALAPPDATA%\Dari\logs` on Windows). The log records failures only, never message contents.

## Uninstall

- **macOS**: quit Dari and move `/Applications/Dari.app` to the Trash. To remove its settings and log too, delete `~/Library/Logs/Dari` and `~/Library/Preferences/io.github.easyhooon.plist`.
- **Windows**: **Settings → Apps → Installed apps → Dari → Uninstall**. Settings live in the registry under `HKEY_CURRENT_USER\Software\JavaSoft\Prefs\io\github\easyhooon`, and the log in `%LOCALAPPDATA%\Dari`.
