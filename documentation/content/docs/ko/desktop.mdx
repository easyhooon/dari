title: 데스크톱 앱
description: adb로 연결해 컴퓨터에서 브릿지 메시지를 확인합니다
---

Dari 데스크톱 앱은 연결된 디버그 빌드의 브릿지 메시지를 컴퓨터 화면에서 보여 줍니다. 실시간 목록, 요청과 응답을 나란히 놓은 상세 화면, 접고 펼칠 수 있는 JSON을 제공합니다. `dari` 2.0.0 이상이 필요하고, 실기기와 에뮬레이터 모두에서 동작합니다. macOS 10.15 이상을 지원하고 Windows는 미리보기(preview)로 제공하며, Linux 빌드는 추후 제공할 예정입니다.

## 설치

### macOS: 터미널로 설치

가장 빠른 방법입니다. Mac의 칩에 맞는 빌드를 골라 릴리스의 SHA-256 파일로 검증한 뒤,
`/Applications/Dari.app`에 설치하거나 업데이트합니다.

```bash
curl -fsSL https://raw.githubusercontent.com/easyhooon/dari/main/scripts/install-desktop.sh | bash
```

손상된 다운로드는 체크섬으로 걸러내므로, 이 명령은 이 페이지나 저장소에 있는 것만 사용하세요. 특정 버전을 설치하려면 `bash` 앞에 `DARI_VERSION=2.0.0`을 붙입니다.

### macOS: DMG로 설치

1. [다운로드 페이지](/ko/download)나 [릴리스 페이지](https://github.com/easyhooon/dari/releases)에서 `Dari-<version>-arm64.dmg`(Apple Silicon) 또는 `Dari-<version>-x64.dmg`(Intel)를 내려받습니다.
2. 이미지를 열고 **Dari**를 **응용 프로그램** 폴더로 끌어 놓습니다.
3. 필요하면 `shasum -a 256 Dari-<version>-arm64.dmg` 결과를 같은 릴리스의 `.sha256` 파일과 비교합니다. 값이 같으면 파일이 손상되지 않았다는 뜻이며, 배포자가 누구인지까지 증명하지는 않습니다.

Dari는 Developer ID로 서명되고 Apple 공증을 받았기 때문에 보안 경고 없이 열립니다. Dari는 저장소의 릴리스 페이지에서만 내려받으세요.

### Windows (preview)

1. [릴리스 페이지](https://github.com/easyhooon/dari/releases)에서 `Dari-<version>-x64.msi`를 내려받아 실행합니다. 현재 사용자 계정에만 설치됩니다.
2. 설치 파일에 코드 서명이 없어서 처음 실행할 때 SmartScreen 경고가 뜰 수 있습니다. **추가 정보 → 실행**을 누릅니다.
3. 필요하면 `certutil -hashfile Dari-<version>-x64.msi SHA256` 결과를 같은 릴리스의 `.sha256` 파일과 비교합니다.

### 다운로드 크기

2.2.0 기준으로 macOS 다운로드가 Windows보다 약 11MB 큽니다.

| | Windows (`.msi`) | macOS (`.dmg`, Apple Silicon) |
| --- | --- | --- |
| 압축 전 | 119.3 MB | 127.1 MB |
| 압축 방식 | `MSZIP` | `UDZO` (zlib 레벨 1) |
| 다운로드 | 59.6 MB | 70.7 MB |

두 설치 파일에는 같은 앱이 들어 있습니다. jlink로 줄인 Java 런타임, 앱 jar, 그리고 Compose가 화면을 그릴 때 쓰는 Skia 네이티브 라이브러리 Skiko입니다. 압축도 둘 다 Deflate를 씁니다. Deflate는 zip과 gzip이 쓰는 알고리즘으로, LZ77로 반복되는 바이트를 줄이고 Huffman 코딩으로 한 번 더 줄입니다.

- **`MSZIP`**: MSI는 파일을 CAB 아카이브에 담고, `MSZIP`은 이를 32KB 블록 단위로 Deflate 압축합니다. jpackage는 WiX의 이 기본값을 그대로 씁니다.
- **`UDZO`**: DMG는 압축된 디스크 이미지이고, `UDZO`는 이미지를 Deflate의 얇은 래퍼인 zlib으로 압축합니다. `hdiutil`은 따로 지정하지 않으면 가장 빠르고 가장 덜 줄어드는 zlib 레벨 1을 씁니다.

그래서 차이는 두 가지에서 납니다.

1. **macOS의 네이티브 라이브러리가 더 큽니다.** `libskiko-macos-arm64.dylib`이 20.8MB, `libjvm.dylib`이 15.7MB입니다. Windows에서는 런타임의 `lib/modules`를 빼면 12.7MB를 넘는 파일이 없습니다. 파일별로 Deflate 압축하면 macOS 앱은 65.8MB, Windows CAB은 58.4MB입니다.
2. **zlib 레벨 1.** 여기서 약 5MB가 더 붙습니다.

macOS 쪽은 이렇게 측정합니다.

```bash
./gradlew :dari-desktop-app:createDistributable
cd dari-desktop-app/build/compose/binaries/main/app
du -sh Dari.app Dari.app/Contents/runtime Dari.app/Contents/app
hdiutil create -srcfolder Dari.app -format UDZO -imagekey zlib-level=9 Dari-level9.dmg
```

```
121M	Dari.app
 66M	Dari.app/Contents/runtime
 54M	Dari.app/Contents/app
```

`du -h`는 MiB 단위라서 121M은 127MB입니다. 같은 `Dari.app`을 다른 DMG 형식으로 묶은 결과입니다.

| 형식 | 알고리즘 | 지원 macOS | 크기 |
| --- | --- | --- | --- |
| `UDZO`, 레벨 1 (`hdiutil` 기본값) | zlib (Deflate) | 모든 버전 | 70.8 MB |
| `UDZO`, 레벨 9 | zlib (Deflate) | 모든 버전 | 67.3 MB |
| `ULFO` | LZFSE: Apple이 만든 LZ77 + 유한 상태 엔트로피 코딩. 압축 해제가 빠름 | 10.11 이상 | 67.3 MB |
| `ULMO` (2.2.0 이후 릴리스) | LZMA: 큰 사전을 쓰는 LZ77 + 범위 코딩. 7-Zip, xz와 같은 방식 | 10.15 이상 | 59.5 MB |

2.2.0 이후 릴리스는 `ULMO`를 써서 DMG 크기를 Windows와 비슷하게 줄였습니다. `ULMO`는 macOS 10.15 이상에서만 열리므로 Dari도 10.15 이상을 요구합니다. Apple Silicon Mac은 처음부터 macOS 11 이상이라 영향이 없습니다.

### 업데이트

Dari는 실행할 때와 6시간마다 릴리스 페이지를 확인합니다. 새 버전이 있으면 타이틀 바에 **Update to &lt;version&gt;** 버튼이 나타나고, **Help → Install Dari &lt;version&gt;** 메뉴도 같은 동작을 합니다.

- **macOS**: 새 이미지를 내려받아 `.sha256`, 번들 ID, 버전, 코드 서명을 확인한 뒤 앱을 종료하고 새 버전으로 다시 엽니다. 중간에 실패하면 설치된 버전을 그대로 둡니다. **응용 프로그램**처럼 쓰기 권한이 있는 폴더에 설치된 경우에만 동작하고, 그 외에는 Dari를 **응용 프로그램** 폴더로 옮겨 그곳에서 열라고 안내합니다.
- **Windows**: 버튼이 다운로드 페이지를 엽니다. 새 `.msi`를 실행하면 설치된 앱이 업그레이드됩니다.

## 연결

1. `adb`를 쓸 수 있게 합니다. Android Studio를 기본 위치에 설치했다면 이미 들어 있고, Dari는 `ANDROID_HOME`도 확인합니다. Android Studio가 없다면 [SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)를 설치합니다. macOS는 `brew install android-platform-tools`, Windows는 압축을 푼 뒤 `platform-tools` 폴더를 `PATH`에 추가합니다.
2. USB 디버깅을 켠 기기를 연결하거나 에뮬레이터를 실행합니다.
3. `dari`를 쓰는 앱의 debuggable 빌드를 실행하고 화면 맨 앞에 띄웁니다.

Dari가 기기와 앱을 알아서 찾아 연결합니다. 기기가 여러 대면 타이틀바에서 고르거나, `ANDROID_SERIAL`을 지정하고 Dari를 실행합니다. 기기가 앱 목록을 보여 주지 않으면 applicationId를 직접 입력합니다.

데스크톱 앱이 연결된 동안에는 앱 내 알림과 흔들어서 열기가 잠시 멈추고, 연결이 끊기면 다시 켜집니다.

## 연결 원리

프록시, 인증서, Wi-Fi, 포트 같은 설정이 필요 없습니다.

1. 앱이 기기 안에만 존재하는 이름 있는 소켓 `dari_<applicationId>`를 엽니다.
2. 데스크톱 앱이 `adb forward tcp:0 localabstract:dari_<applicationId>`를 실행합니다. adb가 컴퓨터의 빈 포트를 하나 골라 열고, USB를 통해 그 소켓으로 이어 줍니다.
3. 데스크톱 앱이 `127.0.0.1:<port>`로 통신하면 adb가 데이터를 앱으로 전달합니다.

이 터널은 데스크톱 앱의 연결이 끊기거나 앱을 종료하면 정리됩니다. 열려 있는 터널은 `adb forward --list`로 확인할 수 있습니다.

## 개인정보 보호

- **직접 허용하지 않는 한 디버그 빌드에서만 동작합니다.** 소켓은 debuggable 빌드, 또는 아래 매니페스트 항목을 넣은 debuggable이 아닌 내부 빌드에서만 열립니다. release 빌드에 들어가는 `dari-noop`에는 캡처 코드가 없습니다.
- **adb만 접속할 수 있습니다.** adb(shell)와 root만 접속할 수 있어서, 기기의 다른 앱은 메시지를 읽을 수 없습니다.
- **가리기는 직접 켭니다.** 기본으로는 앱 내 설정과 상관없이 캡처한 그대로 데스크톱 앱에 보냅니다. 데스크톱 앱 설정에서 **Mask sensitive values**를 켜면, 기기 밖으로 나가기 전에 `token`, `password`, `secret`, `cookie`, `authorization` 같은 키의 값과 `Bearer` 인증 값을 기기에서 가립니다. 앱 내 설정과는 따로 동작합니다. dari 2.2.0보다 오래된 버전은 항상 가립니다. 정확한 기준은 [마스킹](./masking)을 참고하세요.
- **내 컴퓨터의 정보는 밖으로 나가지 않습니다.** 데스크톱 앱에는 분석이나 텔레메트리가 없습니다. 네트워크 요청은 업데이트 확인뿐입니다. 실행할 때와 6시간마다 `github.com`에 요청하며, 일반 브라우저 접속과 같은 정보 외에는 보내지 않습니다. `dari.log`는 내 컴퓨터에만 남고 오류만 기록합니다.

가리는 규칙을 직접 추가할 수 있습니다. 모든 메시지에 실행되고, 기본 마스킹이 켜져 있으면 그다음에 실행됩니다. 규칙에서 예외가 나면 그 메시지는 보내지 않습니다.

```kotlin
Dari.setPayloadRedactor { entry ->
    entry.copy(requestData = entry.requestData?.replace(Regex("\"phone\":\"[^\"]*\""), "\"phone\":\"***\""))
}
```

소켓을 아예 열지 않으려면:

```kotlin
Dari.setDesktopInspectorEnabled(false)
```

스테이징처럼 debuggable이 아닌 내부 빌드는 매니페스트에 다음 항목을 넣으면 사용할 수 있습니다.

```xml
<meta-data
    android:name="com.easyhooon.dari.desktop.ALLOW_NON_DEBUGGABLE"
    android:value="true" />
```

## 데스크톱 전용

QA에 쓰는 스테이징 빌드처럼 데스크톱 앱에서만 메시지를 보고 싶은 빌드에는 다음 항목을 넣습니다. 알림을 띄우지 않고, 흔들어도 열리지 않으며, 런처 바로가기도 지웁니다. 메시지는 그대로 캡처되고 데스크톱 앱에서 평소처럼 볼 수 있습니다.

```xml
<meta-data
    android:name="com.easyhooon.dari.DESKTOP_ONLY"
    android:value="true" />
```

debuggable이 아닌 빌드는 위의 `ALLOW_NON_DEBUGGABLE`도 함께 넣어야 합니다. 그렇지 않으면 메시지를 볼 곳이 없습니다.

## 문제 해결

| 상태 | 해결 방법 |
| --- | --- |
| adb not found | `ANDROID_HOME`을 설정하거나 `platform-tools`를 `PATH`에 추가한 뒤 Dari를 다시 엽니다. |
| No device | `adb devices`로 확인하고, 기기에 뜬 USB 디버깅 허용 창을 수락합니다. |
| App is in the background | Android는 백그라운드 앱을 일시 정지합니다. 앱을 화면 맨 앞에 띄우면 Dari가 다시 연결합니다. |
| Not running Dari | 앱이 `dari` 2.0.0 이상을 쓰는 debuggable 빌드인지 확인합니다. |

문제를 알리려면 **Help → Report an Issue…**를 누릅니다. Dari 버전과 OS가 채워진 버그 양식이 열립니다. 기능 제안은 **Help → Suggest a Feature…**를 누릅니다. **Help → Show Log File**은 `dari.log`가 있는 폴더를 엽니다(macOS `~/Library/Logs/Dari`, Windows `%LOCALAPPDATA%\Dari\logs`). 로그에는 오류만 기록되고 메시지 내용은 남지 않습니다.

## 제거

- **macOS**: Dari를 종료하고 `/Applications/Dari.app`을 휴지통으로 옮깁니다. 설정과 로그까지 지우려면 `~/Library/Logs/Dari`와 `~/Library/Preferences/io.github.easyhooon.plist`를 삭제합니다.
- **Windows**: **설정 → 앱 → 설치된 앱 → Dari → 제거**를 누릅니다. 설정은 레지스트리 `HKEY_CURRENT_USER\Software\JavaSoft\Prefs\io\github\easyhooon`에, 로그는 `%LOCALAPPDATA%\Dari`에 있습니다.

## 소스에서 빌드

```bash
git clone https://github.com/easyhooon/dari.git
cd dari
./gradlew :dari-desktop-app:run
```
